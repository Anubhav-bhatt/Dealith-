# Threat model

Status: Phase 0 design review, 2026-09-07. Scope: browser/edge/API/backend/PostgreSQL/outbox/workers/private objects/providers and staff. Sources: master §§46–47, 68, 70, 76 and 97; [security](SECURITY_MODEL.md), [architecture](MASTER_ARCHITECTURE.md). No penetration test has run.

Assets are confidential business/source/KYC information, credentials, legal/signature evidence, access decisions, money-movement instructions, ownership records and audit continuity. Adversaries include unauthenticated attackers, malicious buyers/sellers, compromised members/staff/providers, malicious uploads/dependencies and insiders. Authorized actors may misuse their permitted scope. Availability failures can also violate integrity when recovery assumes an unknown provider outcome.

| Threat ID | Boundary and abuse | Required mitigation / invariant | Verification and owner / gate |
|---|---|---|---|
| THR-001 | Attacker replays session/reset token or fixes a victim session | Rotation, hashed single-use purpose-bound challenges, rate controls, audience/expiry/revocation checks | AUTH baseline plus replay/recovery tests; Identity / 2 |
| THR-002 | Member substitutes another organization's or deal's IDs | Scoped query and DTO, active representation, composite relation integrity, RLS without privileged bypass | All NEG-A scenarios; two organizations, similar roles, unrelated deals; Security / 2 onward |
| THR-003 | Seller injects script through description, filename, preview or SVG | Context encoding, safe rich-text model, isolated sanitized derivatives, CSP; no seller runtime | Stored/reflected payload and browser-origin tests; Projects / 3 |
| THR-004 | External demo/repository URL reaches metadata or internal service | Approved hosts, resolved-address/redirect checks, deny internal ranges, bounded isolated fetch, no ambient credentials | DNS/redirect/private-address cases; Integrations / 3, 7 |
| THR-005 | Archive bomb/malware or scan outage delivers harmful files | Quarantine, type/size/recursion/resource limits, isolated scan/render; unknown never CLEAN | Upload, timeout and rescan cases; Documents / 3, 8 |
| THR-006 | Expired grant leaks through URL, cache, websocket, export or queued AI | Authoritative policy version and reauthorization per delivery; bounded bearer lifetime; gateway for restricted originals | Revocation race; inspect bytes/caches, not only buttons; Documents/Security / 6–8 |
| THR-007 | Buyer guesses NDA version or provider callback to unlock evidence | Exact scope/hash/signers and authoritative verified receipt, current grant independently required | Wrong signer/version, unsigned/duplicate callback, expired NDA; NDA / 8 |
| THR-008 | Concurrent offers accept conflicting rights or overwrite terms | Immutable revisions, expected version, unique rights reservation and atomic coordinator | Two concurrent buyers, same revision replay, expiration race; Deals / 9 |
| THR-009 | Callback forgery, unordered duplicate or timeout creates/repeats money movement | Signed raw inbox, provider/account/environment scope, stable operations, unique movement journal, reconcile unknown outcomes | Crash/replay/wrong account/digest/out-of-order; Settlement / 11 |
| THR-010 | Destination substitution or staff self-approval diverts release | Frozen destination/amount/agreement, fresh step-up and distinct approvals, current hold check before dispatch | Change while queued; release/refund/dispute race; Settlement / 11–12 |
| THR-011 | Seller claims transfer complete without intended recipient evidence | Agreement-specific checklist, separate submission/acceptance, inspection, provider truth, dispute hold | Missing/wrong recipient, forged evidence, release before acceptance; Transfer / 12 |
| THR-012 | Prompt injection or cross-tenant retrieval leaks data or executes action | Model has no transactional tools; authorized source manifest, redaction, output validation, all-source policy intersection | Adversarial source, invented citation, revoked source; Intelligence / 7 |
| THR-013 | Staff escalates role or erases audit to hide abuse | Separate audience/MFA, scoped case, no self-approval, immutable action evidence, independent audit archive | Staff separation, unauthorized export/mutation, audit tamper; Security / 3, 13 |
| THR-014 | Lost Redis/outbox replay silently loses state or duplicate effects | PostgreSQL intent and receipts authoritative, transactional effects/receipt, leases and bounded retries | Restart/crash/rebuild tests with invariant comparison; Platform / 1 onward |
| THR-015 | Compromised dependency/PR steals secrets or deploys altered code | Secret-free untrusted jobs, narrow OIDC, reviewed dependencies, immutable artifacts and protected promotion | CI permission review, provenance and scan evidence; Platform / 1, 15 |
| THR-016 | Restore reactivates revoked users or loses financial/audit facts | Freeze writes, reconcile revocations/provider activity/audit, verify hashes/checkpoints before reopen | Timed isolated restore and unknown-operation reconciliation; SRE / 15 |
| THR-017 | Public indexing, analytics or AI inference reveals private metrics | Public projection only, recheck eligibility, private no-store, minimized/suppressed aggregates, independent source policy | Suspend listing while index stale; payload/facet/metadata assertions; Search / 4, 7 |
| THR-018 | Fraudulent claims or paid placement masquerade as verified ownership | Versioned claim/evidence lineage, independent review, expiry, labeled promotion, no purchased trust badge | False/expired provenance and owner/reviewer separation; Verification / 3, 7 |
| THR-019 | Subscription or edited client flag activates restricted transaction | Server intersection of policy, jurisdiction, eligible parties, provider capability and environment | Unknown scope/default-off/revoked approval rejection; Compliance / 11, 14–15 |
| THR-020 | Enumeration/resource exhaustion blocks critical flows | Scoped counts, bounded pagination/upload/AI budgets, fair queues, rate limits; security events preserve privacy | Bursts and noisy-tenant tests; SRE / 1, 15 |

Residual risks include screenshots after lawful disclosure, compromised external providers, unverified commercial claims and unsupported recovery capabilities. They require the explicit mitigation and launch gates in the [risk register](PROJECT_RISK_REGISTER.md); they are not accepted merely because listed here. Provider outages preserve pending/unknown outcomes and assigned review.

Revisit this model for every new integration, data class, transaction rail, tenant relationship and change to signature/funding/authorization semantics. Record trust-boundary delta, new abuse scenarios, owner, tests and ADR. Phase 0 checks the model and references; relevant implementation phases must demonstrate each mitigation under adversarial conditions.

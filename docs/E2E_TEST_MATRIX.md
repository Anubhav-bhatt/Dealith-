# End-to-end test matrix

Status: Phase 0 scenario design, 2026-09-07. All cases below are **PLANNED, NOT RUN**. Sources: master §§63–70 and 95. Every master §67 scenario is preserved as an alias; E2E IDs are the canonical cross-document identifiers. Browser/API integration tests use synthetic data and real applicable backing services. Provider flows use fakes plus sandbox contracts, never real money.

Each row requires both positive and negative evidence, state/audit/outbox observations where applicable, and absence of sensitive fields/bytes in denied or public payloads. Test reports capture exact case/alias, artifact or commit when available, environment, clock/seed, actor/tenant, commands, assertions and sanitized diagnostics. [Test strategy](TEST_STRATEGY.md) defines tools, coverage and failures.

Each critical workflow also runs the applicable loading, empty, error, denied, expired-access and network variants from [UI architecture](UI_INFORMATION_ARCHITECTURE.md). Project lifecycle tests enumerate all 17-state ordered pairs; Deal tests enumerate all 28-state ordered pairs, including self-pair rejection for lifecycle transitions (same-state content commands are separate). Every allowed edge additionally varies actor, guard, clock and aggregate version. Exhaustive enumeration is an implementation requirement, not a claim that this document executed it.

A failing critical case blocks its feature/phase. Retries can collect evidence but do not waive failures. Runtime test IDs link to this catalog; new scenarios append without renumbering existing IDs. Provider-specific capabilities and approved legal templates may require additional cases before enablement.
